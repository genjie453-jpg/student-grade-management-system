## 1. 系统架构与数据模型

### 1.1 功能与角色

| 功能 | 管理员 | 教师 | 学生 |
|---|:--:|:--:|:--:|
| 录入成绩 | ✅ | ✅ | ❌ |
| 修改成绩 | ✅ | ✅ | ❌ |
| 修改学生信息（姓名/班级） | ✅ | ❌ | ❌ |
| 删除记录 | ✅ | ❌ | ❌ |
| 多条件查询 | ✅ | ✅ | 仅本人 |
| 统计分析 | ✅ | ✅ | 仅本人 |
| 保存文件 | ✅ | ✅ | ❌ |

两种运行模式共用同一套内存结构与算法：

- **控制台模式**：`main.c` 菜单 → 直接调用 `list_*`；
- **页面模式**：`webui.c` 内置 HTTP 服务器 → `/api/*` → 调用同一批 `list_*`。

### 1.2 记录模型：把「成绩」做成事实表

```c
typedef struct Student {
    char  id[MAX_ID_LEN];           // 学号，16
    char  name[MAX_NAME_LEN];       // 姓名，32
    char  className[MAX_CLASS_LEN]; // 班级，32
    char  term[MAX_TERM_LEN];       // 学期，16
    char  course[MAX_COURSE_LEN];   // 课程，32
    float score;                    // 成绩
} Student;                          // src/student.h:31-38
```

**设计取舍**：

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 一条记录 = 一个学生的全部课程（二维表） | 学生信息不冗余，改名一次搞定 | 课程数不定，C 里要变长数组；按课程查询要遍历内层 |
| B. 一条记录 = 一个学生的一门课（本项目） | 定长结构、按任意字段线性筛选简单、统计直接拍平 | 姓名/班级冗余，改名需批量同步 |

选 B 的理由：课程设计的核心是**链表 + 查找 + 排序**，B 让每条记录独立、结构定长、文件一行一条，最简单也最不容易出错。

```
                └── 每个 Node 24 + 1 字节指针开销，记录体 ~= 132 字节
```

## 2. 线性表：单向链表

### 2.1 为什么用链表而不是顺序表

| 操作 | 顺序表 | 单向链表 |
|---|---|---|
| 按位访问 | O(1) | O(n) |
| 已知位置插入/删除 | O(n)（搬移） | O(1)（改指针） |
| 头部插入 | O(n) | O(1) |
| 扩容 | realloc + 拷贝 | 天然 |
| 缓存局部性 | 好 | 差 |

本系统的真实负载是「**读多写少、按内容查、不按位访问**」：

- 查询必须遍历全表（顺序表也一样要扫），链表的 O(n) 不吃亏；
- 录入/删除是主要写操作，链表不需要搬移；
- 规模在千级，缓存局部性差异可忽略；
- 课程设计明确要求练习链表。

### 2.2 节点定义

```c
typedef struct Node {
    Student data;        // 记录本体
    struct Node* next;   // 后继指针
} Node;                  // src/list.h:8-12
```

**不带头结点（dummy head）**：`g_head` 直接指向第一个元素。好处是结构简单；代价是**所有涉及头部的操作都要特判**（删除头节点、头插）。

### 2.3 尾插法

`src/list.c:20-38`

```c
Node* list_insert_tail(Node* head, Student s) {
    Node* node = malloc(sizeof(Node));
    if (!node) return head;              // 分配失败：保持原表

    node->data = s;
    node->next = NULL;

    if (head == NULL) return node;       // 空表：新节点即表头

    Node* p = head;
    while (p->next != NULL) p = p->next; // 走到最后一个节点
    p->next = node;
    return head;
}
```

**为什么返回新头指针**：空表插入会改变 `head`，而 C 没有引用参数，只能靠返回值回传。调用方统一写 `head = list_insert_tail(head, s);`。

**成本推导**：第 i 次插入要走 i−1 步，建 N 条表的总步数

```
0 + 1 + 2 + ... + (N−1) = N(N−1)/2
```

| N | 指针跳转次数 | 量级 |
|---|---|---|
| 13（当前示例数据） | 78 | 可忽略 |
| 1,000 | 499,500 | 可忽略 |
| 10,000 | 49,995,000 | 明显卡顿 |
| 100,000 | 4,999,950,000 | 不可接受 |

**改进**：维护尾指针 `tail`，插入降为 O(1)，总建表 O(N)：

```c
Node* list_append(Node** phead, Node** ptail, Student s) { ... }
```

（代价：删除尾节点后 `tail` 失效，需要回退或改双向链表。）

**为什么仍然选尾插**：文件加载要求保持原始顺序（便于比对、导出），头插会整体逆序。

### 2.5 查找

**按学号**（`src/list.c:42-48`）：

```text
for p in list:
    if strcmp(p->data.id, id) == 0: return p
return NULL
```

**按复合键**（`src/list.c:50-58`）：`学号 + 学期 + 课程` 三字段全等。

```text
if (strcmp(id) == 0 && strcmp(term) == 0 && strcmp(course) == 0) return p
```

C 的 `&&` 短路：第一个字段不等就不再比较后两个，平均比较次数约 1 + 1/|Σ|。

**为什么用复合键**：同一个人同一学期有多门课；只按学号定位不到唯一记录。

**复杂度**：O(n·L)，L 为字段长度。n=13 时最坏 13 次 `strcmp`。

### 2.6 删除：双指针法

`src/list.c:67-88`

```c
Node* list_delete_one(Node* head, const char* id, const char* term,
                      const char* course, int* deleted) {
    Node *prev = NULL, *cur = head;
    *deleted = 0;

    while (cur != NULL) {
        if (strcmp(cur->data.id, id) == 0
            && (term   == NULL || term[0]   == '\0' || strcmp(cur->data.term, term) == 0)
            && (course == NULL || course[0] == '\0' || strcmp(cur->data.course, course) == 0)) {

            if (prev == NULL) head = cur->next;   // ① 删头节点
            else              prev->next = cur->next; // ② 删中间/尾节点

            free(cur);
            *deleted = 1;
            return head;
        }
        prev = cur;
        cur = cur->next;
    }
    return head;
}
```

**图解**：

```
删除中间节点 B：
      prev        cur
       ↓           ↓
  [A] ───────► [B] ───────► [C]
                 
  执行 prev->next = cur->next 后：
  [A] ─────────────────────► [C]        B 被 free

删除头节点 A：
  head ──► [A] ──► [B]
  执行 head = cur->next 后：
  head ──────────► [B]
```

**三个必须特判的点**：

1. **空表**：`cur == NULL`，循环不进入，返回原 head；
2. **删头**：`prev == NULL`，必须改 `head` 本身（C 里通过返回值）；
3. **找不到**：`*deleted = 0`，调用方据此判断。

**空字符串语义**：`term`/`course` 传 `""` 表示「该维度不限制」，于是可以「删该生全部记录」。控制台用循环反复调用直到 `deleted == 0`：

```c
for (;;) {
    g_head = list_delete_one(g_head, id, term, course, &deleted);
    if (!deleted) break;
}
```

k 条匹配时总成本 **O(k·n)**（每次从头扫）。

**改成绩**（`src/list.c:92-99`）：先 `list_find_record` 定位，再改 `score`，O(n)。

**改学生信息**（`src/list.c:101-117`）：

```c
Node* p = list_find_by_id(head, id);
if (p == NULL) return 0;
for (; p != NULL; p = p->next) {     // 注意：从这里一直扫到表尾
    if (strcmp(p->data.id, id) != 0) continue;
    if (newName && newName[0])  strncpy(p->data.name, newName, MAX_NAME_LEN - 1);
```

**复杂度**：O(n)。

### 2.8 遍历类操作

| 函数 | 位置 | 说明 | 复杂度 |
|---|---|---|---|
| `list_count` | `src/list.c:121-127` | 计数 | O(n) |

```c
void list_destroy(Node* head) {
    while (head != NULL) {
        Node* next = head->next;   // 必须先保存
        free(head);
        head = next;
    }
}
```

### 2.9 链表正确性的四个易错点

| 场景 | 错误写法 | 后果 |
|---|---|---|
| 删除头节点 | 只改 `prev->next`，忘了 `head` | 头节点泄漏，后续遍历从已 free 内存开始 |
| 释放顺序 | 先 `free(cur)` 再读 `cur->next` | 读已释放内存（UB） |
| 空表插入 | 直接 `head->next = node` | 空指针解引用 |
| 重复删除 | 忘记把 `*deleted` 复位 | 循环删空表后继续访问 |

## 3. 哈希索引：FNV-1a + 链地址法

### 3.1 动机

按学号查是最高频的操作（登录后查本人、录入前查重）。链表 O(n) 在 n=10⁴ 时每次要跳 5000 次。哈希表把平均查找降到 O(1+α)。

### 3.2 FNV-1a 哈希函数

`src/index.c:17-25`

```c
static unsigned int hash_id(const char* id) {
    unsigned int h = 2166136261u;          // offset basis（FNV 约定）
    while (*id != '\0') {
        h ^= (unsigned char)(*id++);       // 先异或
        h *= 16777619u;                    // 再乘 FNV 素数（uint32 自然溢出 = mod 2^32）
    }
    return h % INDEX_BUCKETS;              // 折叠到 256 个桶
}
```

**为什么用 FNV-1a**：

- 只用一次异或 + 一次乘法，比 CRC/ MD5 快一个量级；
- 对短字符串（学号 6~10 位）分布均匀；
- 无查表、无动态内存，`static` 纯函数，线程安全。

**为什么先异或再乘**（FNV-1a 与 FNV-1 的区别）：FNV-1 是先乘后异或，最后一位字节只参与异或不参与乘法，雪崩性差；1a 让每个字节都经过乘法扩散。

**无符号溢出的合法性**：C 标准规定无符号整型运算按 2³² 取模，不是 UB，正是我们需要的。

### 3.3 冲突处理：链地址法

```c
typedef struct IdxEntry {
    char id[MAX_ID_LEN];       // 关键字副本
    Node* node;                // 指向链表中该学号的第一条记录
    struct IdxEntry* next;     // 同桶冲突链
} IdxEntry;

static IdxEntry* s_buckets[INDEX_BUCKETS];   // 256 个桶，静态数组
```

```
桶 10:  [230101] → NULL
桶 81:  [230104] → NULL
桶 119: [230102] → [250101] → NULL     ← 若发生冲突，头插成链
```

**为什么不用开放定址法**：开放定址删除需要墓碑标记、装填因子高时性能骤降；链地址法删除简单（摘链）、装填因子可 >1、实现更短。

### 3.4 建索引

`src/index.c:27-57`

```text
index_build(head):
    index_destroy()                       // 清空旧索引
    for p in list:
        b = hash_id(p->id)
        if 桶 b 中已存在相同 id: continue  // 同学号只登记一次
        e = malloc(IdxEntry)
        e.id = p->id; e.node = p; e.next = s_buckets[b]; s_buckets[b] = e
        count++
    return count
```

**为什么只登记第一条**：同一学号有多门课，查「本人所有成绩」时从第一条顺链走即可；索引只负责定位起点。

**桶分布实测**（示例数据 6 个学号）：

| 学号 | FNV-1a（十进制） | 桶号 h % 256 |
|---|---|---|
| 230101 | 3044103690 | **10** |
| 230102 | 3027326071 | **119** |
| 230103 | 3010548452 | **228** |
| 230104 | 2993770833 | **81** |
| 230105 | 2976993214 | **190** |
| 250101 | 2977623544 | **248** |

6 个学号落在 6 个不同桶，无冲突。连续学号只差最后一位，哈希值相差接近 FNV 素数，取模后被打散——说明**低位变化能被乘法扩散到高位**。

### 3.5 查找与负载因子

`src/index.c:59-68`

```text
index_lookup(id):
    if id 为空: return NULL
    b = hash_id(id)
    for e in 桶 b 的冲突链:
        if strcmp(e->id, id) == 0: return e->node
    return NULL
```

- 平均查找长度 **1 + α/2**（成功查找），α = N / 256；
- 本项目 N ≈ 13 → α ≈ 0.05，几乎必然一次命中；
- N = 10,000 → α ≈ 39，链长 39，退化为 O(39)，仍远好于 O(10⁴)。

**为什么是 256**：2 的幂便于编译器把 `% 256` 优化成 `& 255`（GCC/Clang 对无符号取模会做此优化）；而 256 桶 × 8 字节指针仅 2KB 静态内存。

### 3.6 索引失效问题（重要）

`index_build` **只在 `main()` 启动时调用一次**（`src/main.c:340`）。之后：

- 新增记录 → 索引里没有；
- 删除记录 → 索引里存的是**已 free 的节点指针**（悬空）；
- 修改学号（本系统不支持）→ 键值错。

因此直接接上 `index_lookup` 会读到野指针。**正确做法**：每次写操作后重建（O(n)，对千级数据可接受），或改成「延迟重建 + 脏标记」。

### 3.7 与其它方案的对比

| 方案 | 查找 | 插入 | 删除 | 内存 | 实现量 |
|---|---|---|---|---|---|
| 链表遍历 | O(n) | O(1)* | O(n) | 最小 | 已实现 |
| 哈希索引（链地址） | O(1+α) | O(1) | O(1)+重建 | +2KB | 中 |
| 平衡树（AVL/红黑） | O(log n) | O(log n) | O(log n) | 中 | 大 |
| 跳表 | O(log n) 期望 | O(log n) | O(log n) | 中 | 大 |

*已知尾指针时。

## 4. 排序：三种实现

### 4.1 需求来源

1. 统计页要按分数降序排名 → 需要排序；
2. 表格点表头要按任意列排序 → 前端排序。

### 4.2 控制台：简单选择排序

`src/main.c:81-90`

```c
for (int i = 0; i < n - 1; i++) {
    int max = i;
    for (int j = i + 1; j < n; j++)
        if (arr[j].score > arr[max].score) max = j;
    if (max != i) { Student t = arr[i]; arr[i] = arr[max]; arr[max] = t; }
}
```

**思想**：每轮在未排序区间 `[i, n)` 中选最大者，放到位置 i。

**真实数据演算**（高等数学，6 条，初始顺序 = 文件顺序）：

```
初始: [92.0, 55.5, 88.0, 45.0, 76.5, 100.0]

i=0: 扫描 [0..5] 最大 = 100.0(下标5) → 交换 0↔5
     [100.0, 55.5, 88.0, 45.0, 76.5, 92.0]
i=1: 扫描 [1..5] 最大 = 92.0(下标5)  → 交换 1↔5
     [100.0, 92.0, 88.0, 45.0, 76.5, 55.5]
i=2: 扫描 [2..5] 最大 = 88.0(下标2)  → 不交换
     [100.0, 92.0, 88.0, 45.0, 76.5, 55.5]
i=3: 扫描 [3..5] 最大 = 76.5(下标4)  → 交换 3↔4
     [100.0, 92.0, 88.0, 76.5, 45.0, 55.5]
i=4: 扫描 [4..5] 最大 = 55.5(下标5)  → 交换 4↔5
     [100.0, 92.0, 88.0, 76.5, 55.5, 45.0]
完成
```

**复杂度推导**：

- 比较次数与初始顺序无关：`Σ_{i=0}^{n-2}(n-1-i) = n(n−1)/2`；
- 交换次数：最好 0（已降序），最坏 n−1（每轮都换）；
- 时间 O(n²)，空间 O(1)（原地）；
- **不稳定**：交换会跨过相等元素。

**n=13 时**：78 次比较，几乎无感。

### 4.3 页面：qsort + 三值比较器

`src/webui.c:190-195`

```c
static int cmp_score_desc(const void* a, const void* b) {
    float fa = ((const Student*)a)->score;
    float fb = ((const Student*)b)->score;
    return (fb > fa) - (fb < fa);      // 降序
}
```

**为什么不用 `return fb - fa`**：

1. 返回值是 `int`，两个 float 相减再截断，小差值会变 0（视为相等）；
2. `float` 溢出/NaN 时行为不可控；
3. `(a>b)-(a<b)` 严格输出 −1/0/1，语义清晰。

**注意**：`qsort` 的比较器参数是 `const void*`，必须先转回 `const Student*` 再取字段，不能直接解引用。

**复杂度**：标准库实现（通常为快速排序/内省排序 + 小数组插入排序），平均 O(n log n)，最坏 O(n²)（已排序且取首元素为轴时，现代实现用三数取中规避）。

### 4.4 前端：TimSort + 中文比较

`src/webui.c:373-377`

```js
const arr = [...lastData];
if (sortKey) arr.sort((a, b) => {
    const x = a[sortKey], y = b[sortKey];
    return (sortKey === 'score' ? (x - y) : String(x).localeCompare(String(y), 'zh')) * sortDir;
});
```

- V8 的 `Array.prototype.sort` 自 2019 年起为 **TimSort**（稳定，O(n log n)）；
- 字符串用 `localeCompare(..., 'zh')` 按拼音/笔画排序，而非字节序；
- `sortDir` 为 ±1，点同一表头取反。

### 4.5 三者对比

| 维度 | 选择排序 | qsort | TimSort |
|---|---|---|---|
| 典型时间 | O(n²) | O(n log n) | O(n log n) |
| 最坏时间 | O(n²) | O(n²) | O(n log n) |
| 稳定性 | 否 | 否 | 是 |
| 额外空间 | O(1) | O(log n) 栈 | O(n) |
| 适用 | 教学演示、n 小 | C 端通用 | 前端对象数组 |
| 本项目位置 | 控制台 | 页面统计 | 页面表格 |

**一致性缺口**：同一「排名」功能，控制台 O(n²)、页面 O(n log n)。数据量小时无感，但属于实现不统一，报告里应说明。

## 5. 排名：并列名次

### 5.1 定义

名次 = 1 + 比它严格高的人数（竞赛排名 / 1224 式）：

| 分数 | 100 | 92 | 92 | 85 | 80 |
|---|---|---|---|---|---|
| 名次 | 1 | 2 | 2 | 4 | 5 |

### 5.2 当前实现（O(n²)）

`src/main.c:104-111`、`src/webui.c:225-230`

```c
for (int i = 0; i < n; i++) {
    int rank = 1;
    for (int j = 0; j < i; j++)
        if (arr[j].score > arr[i].score) rank++;
    printf("%d", rank);
}
```

数组已降序，`j < i` 的元素分数都 ≥ 当前，因此只需统计严格大于者。

### 5.3 优化：单遍 O(n)

```c
rank[0] = 1;
for (int i = 1; i < n; i++)
    rank[i] = (arr[i].score == arr[i-1].score) ? rank[i-1] : i + 1;
```

**正确性**：若与前一个同分，则名次相同；否则前面 i 人全部严格更高，名次 = i+1。

**收益**：n=10⁴ 时，排名从 5×10⁷ 次比较降到 10⁴ 次。

### 5.4 三种并列口径

| 口径 | 分数 100/92/92/85 | 说明 |
|---|---|---|
| 竞赛排名（本项目） | 1 / 2 / 2 / 4 | 跳号 |
| 密集排名 | 1 / 2 / 2 / 3 | 不跳号 |
| 序位排名 | 1 / 2 / 3 / 4 | 不并列 |

## 7. 多条件查询

### 7.1 合取模型

五个条件全部为「与」，空条件视为恒真：

```text
result = { r ∈ R | (id="" ∨ r.id=id) ∧ (name="" ∨ r.name=name) ∧ ... }
```

### 7.2 短路求值

`src/webui.c:76-85`

```c
static int match(Node* p, const char* id, const char* name,
                 const char* className, const char* term, const char* course) {
    if (id[0]        && strcmp(p->data.id, id))                return 0;
    if (name[0]      && strcmp(p->data.name, name))            return 0;
    if (className[0] && strcmp(p->data.className, className))  return 0;
    if (term[0]      && strcmp(p->data.term, term))            return 0;
    if (course[0]    && strcmp(p->data.course, course))        return 0;
    return 1;
}
```

**条件顺序**：学号唯一性最高、姓名其次，放前面能最快排除。当前顺序（id → name → class → term → course）基本符合选择性从高到低。

**复杂度**：O(N·m·L)，m=5，L≈16。

### 7.3 两次扫描问题

`api_list` 为了先输出 `total`，扫了两遍：

```c
for (p = head; p; p = p->next) if (match(...)) total++;   // 第一遍：计数
for (p = head; p; p = p->next) if (match(...)) { ... }    // 第二遍：输出
```

**改进方案**：

1. 先序列化 data 到缓冲，最后回填 `total`（需要预留长度或二次 memmove）；
2. 用可增长缓冲，一次遍历同时计数与追加；
3. 前端不需要 total 时直接去掉。

### 7.4 若要支持大数据

| 方案 | 思路 | 代价 |
|---|---|---|
| 倒排索引 | 每个字段值 → 记录下标集合 | 写放大、需维护 |
| 位图 | 每个条件算位图，按位与 | 内存 O(N/8)/字段值 |
| 数据库 | 交给 SQLite | 引入依赖 |

课程设计规模不需要。

## 8. 字符串与协议解析

### 8.1 URL 解码

`src/webui.c:22-37`

```c
static void url_decode(char* dst, const char* src, int dstSize) {
    int di = 0;
    for (int i = 0; src[i] && di < dstSize - 1; i++) {
        if (src[i] == '+') dst[di++] = ' ';
        else if (src[i] == '%' && src[i+1] && src[i+2]) {
            char hex[3] = { src[i+1], src[i+2], '\0' };
            dst[di++] = (char)strtol(hex, NULL, 16);
            i += 2;
        } else dst[di++] = src[i];
    }
    dst[di] = '\0';
}
```

**算法**：单遍状态扫描，O(L)。

**边界缺陷**：`%G1` 这类非法十六进制，`strtol` 返回 0，会在字符串中间写入 `\0` 造成**截断**（而不是报错）。严格实现应校验 `isxdigit`。

### 8.2 查询串解析

`src/webui.c:42-57`

```text
先按 '&' 切分（strtok_s），再对每段按 '=' 切分
key 截断到 23 字节，value 经 url_decode 到 128 字节
最多 16 个参数，超出丢弃
```

**注意**：`strtok_s` 会**修改原缓冲区**（把分隔符改成 `\0`），因此 `target` 必须是可写内存（`recv` 的缓冲区，满足）。

### 8.3 文本解析

`src/fileio.c:19-23`

```c
while (fscanf(fp, "%15s %31s %31s %15s %31s %f",
              s.id, s.name, s.className, s.term, s.course, &s.score) == 6) {
    head = list_insert_tail(head, s);

```

- 宽度限制与结构体数组长度一致（15/31/31/15/31），防溢出；
- 返回 6 才计入，格式错误时**停止读取**（不是跳过该行）——一行损坏会导致后续全部丢失，属缺陷，改进是 `fgets` + `sscanf` 逐行解析。

### 8.4 JSON 序列化

`src/webui.c:70-73`

## 10. 文件持久化

### 10.1 格式

```
学号 姓名 班级 学期 课程 分数
230101 张三 计科2301 2025-2026-1 高等数学 92.0
```

空格分隔、一行一条、UTF-8。

### 10.2 两种写策略

| 操作 | 方式 | 成本 | 风险 |
|---|---|---|---|
| 录入 | `fopen("a")` 追加 | O(1) | 追加中途失败 → 半行 |
| 修改/删除 | `fopen("w")` 全量重写 | O(N) | 重写中途失败 → **文件被截断** |

**写放大**：删除 1 条记录要重写 N 条，N=10⁴ 时约 1.3MB 写流量/次。

### 10.3 崩溃一致性

当前实现先 `fopen("w")` 截断再写，若进程在写入中途崩溃，原数据**全部丢失**。

**改进（原子替换）**：

```text
1. 写 data/students.txt.tmp
2. fflush + fsync
3. rename(tmp, students.txt)   // 同分区 rename 是原子的
```

### 10.4 无锁假设

服务端单线程串行处理请求，不存在并发写；若改成多线程需加互斥锁。

## 11. HTTP 服务模型

### 11.1 单线程 accept 循环

`src/webui.c:540-563`

```text
for (;;) {
    client = accept(listenSock)          // 阻塞
    set SO_RCVTIMEO = 2000ms
    len = recv(client, req, 8191)
    if (len > 0) 解析请求行 → handle()

```

- 一次只服务一个连接，简单但吞吐低；
- 浏览器会「预连接」但不发数据，若没有接收超时，单线程会被一个空连接**永久阻塞**——这是本项目最关键的工程细节。

### 11.2 请求解析


只接受 `GET`，其余返回 405（`Method Not Allowed`）。

### 11.3 短写处理

`src/webui.c:404-412`

```c
static void send_all(SOCKET sock, const char* buf, int len) {
    int sent = 0;
    while (sent < len) {
        int n = send(sock, buf + sent, len - sent, 0);
        if (n <= 0) break;
        sent += n;
    }
}
```

TCP 发送缓冲区满时 `send` 只发部分字节，必须循环。

### 11.4 绑定与访问控制

`Connection: close` 简化实现（不维护 keep-alive 状态机），代价是每请求一次 TCP 握手。

## 16. 答辩问答

**Q1：为什么用链表而不是数组？**
记录频繁增删，链表改指针即可，不需搬移；查询本来就要全表扫描，链表的 O(n) 不吃亏；且课程设计要求练习链表。

**Q2：尾插法建表为什么是 O(N²)？**
每次插入都要从表头走到表尾，第 i 次走 i−1 步，总计 N(N−1)/2。

**Q3：那为什么不用头插？**
头插 O(1) 但会逆序，加载后与文件顺序不一致，调试和导出都不方便。

**Q4：删除节点要注意什么？**
三件事：空表判断、删头节点时改 head、free 前先保存 next。

**Q5：哈希怎么解决冲突？**
链地址法，256 个桶，桶内单链头插。平均查找 1+α/2。

**Q6：为什么选 256 个桶？**
2 的幂可优化取模；256×8B=2KB 内存可接受；α=N/256，千级数据几乎无冲突。

**Q7：索引为什么没用上？**
`index_build` 只在启动时建，写操作后不重建，直接查会拿到已释放的节点。正确做法是写后重建或加脏标记——这是已知待改进项。

**Q8：排名怎么算的？**
先按分数降序，名次 = 1 + 前面严格更高的人数，同分并列、后续跳号（竞赛排名）。

**Q9：为什么排名是 O(n²)？**
对每个元素都回头数一遍。其实数组已有序，改成一趟比较相邻分数即可 O(n)。

**Q10：多条件查询怎么实现？**
线性扫描 + 五条件短路与；空条件跳过，任一不等立即返回。

**Q11：学生怎么防止越权？**
登录发 token，服务端校验角色；学生请求时用 `force_param` 把 `id` 改写成令牌里的学号，前端改参数无效。

**Q12：系统瓶颈在哪？**
批量导入的 O(N²) 和排名的 O(n²)。千级数据可接受，规模化需改尾指针、单遍排名，并把查询接到哈希索引上。
