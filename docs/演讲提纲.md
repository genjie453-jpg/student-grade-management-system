## 二、逐段脚本

### 0. 开场（30 秒）

> “我做的是学生成绩管理系统，C 语言实现，控制台和浏览器两种模式，数据存在文本文件里。代码分 7 个模块，我按文件顺序讲：认证、文件、索引、链表、主流程、数据模型、界面。其中登录和排序算法是我的重点。”

---

### 1. `auth.c` / `auth.h`（约 2 分 10 秒，**重点**）

> “系统从登录开始。这个模块只回答三个问题：你是谁、你怎么证明、你能干什么。”

#### 1.1 账号表：用户存在哪（20 秒）

- 文件 `data/users.txt`，一行一个账号：`账号 密码 角色 姓名`；
- 启动时 `fscanf` 四个字段 → 每个账号 `malloc` 一个 `User` 节点 → **头插**进链表，O(1)/条（`auth.c:51-61`）；
- 角色是 0/1/2；加载时对非法值兜底成 2（学生），避免脏数据导致越权（`auth.c:57`）；
- 文件不存在时自动生成默认账号（admin、teacher01、230101…），保证首次运行可用。

**一句话**：“账号表就是一条链表，查找靠遍历，因为账号只有个位数。”

#### 1.2 登录：密码怎么验、令牌怎么发（30 秒）

> “登录接口只做两件事：验密码、发令牌。”

```text
浏览器  GET /api/login?account=admin&password=admin123
          │
          ▼
webui.c  api_login()                       （webui.c:275-290）
          │
          ▼
auth.c   auth_login(account, password, &sess)   （auth.c:76-99）
          │
          ├─ 遍历 s_users，strcmp 账号 && strcmp 密码
          ├─ 命中：memset(&sess,0)
          ├─       gen_token(sess.token)        32 位十六进制
          ├─       sess.role / id / name 赋值
          ├─       malloc 一个 Session，头插进 s_sessions
          └─ 返回 1
          │
          ▼
浏览器  {"code":0,"token":"…","role":0,"name":"管理员","id":"admin"}
```

**要点**

- 令牌 32 个字符 = 16 字节（`TOKEN_LEN = 33`，含 `\0`）；
- 会话链表**头插**，O(1)；
- 同一账号可以多次登录，得到多个令牌，互相独立。

#### 1.3 每个请求：令牌怎么校验（20 秒）

> “登录之后，前端每次请求都带 token，服务端用它换回身份。”

- 前端 `api()` 自动给 URL 追加 `&token=…`；
- 服务端 `auth_verify(token, &sess)` 遍历会话链表，`strcmp` 命中即返回会话（`auth.c:101-112`），O(S)，S 通常小于 10；
- 失败返回 `{"code":2}`，前端弹“请先登录”；
- 注销时用**双指针**把节点从链表中摘掉（`auth.c:114-127`）。

#### 1.4 权限判定：登录之后能干什么（20 秒）

| 角色 | 能做什么 |
|---|---|
| 管理员 0 | 全部：录入、修改、删除、改信息、查询、统计、保存 |
| 教师 1 | 录入、修改、查询、统计（**不能删**） |
| 学生 2 | 仅查询本人、统计本人 |

> “权限不是前端藏按钮，而是服务端路由层硬拦截。”

`webui.c:456-491` 里每个 `/api/*` 分支先看 `sess.role`：学生请求 `/api/add` 直接返回“无录入权限”，教师请求 `/api/delete` 返回“仅管理员可删除”。

#### 1.5 越权防护：改 URL 也没用（20 秒）

> “学生如果把 URL 里的 id 改成别人的学号，会发生什么？”

服务端在调用查询前执行 `force_param(ps, &np, "id", sess.id)`（`webui.c:256-272`）：

- 参数里已有 `id` → **覆盖**成本人学号；
- 参数里没有 → **追加**一条。

所以 `/api/list?id=230103` 对学生来说等价于 `/api/list?id=本人`。这是整个系统信任边界的落点。

#### 1.6 安全短板：主动交代（20 秒）

> “这一版是演示级实现，有三处不足：”

1. **密码明文**存在 `users.txt`，生产环境要加盐哈希（bcrypt/scrypt）；
2. **令牌可预测**：`srand(time(NULL))` + `rand()%16`，MSVC 的 `rand` 只有 15 位状态，实际熵远低于 128 bit，应换 `BCryptGenRandom`/`/dev/urandom`；
3. **会话不过期**：没有 TTL，令牌永久有效，应加过期时间并在校验时清理。

**这样讲的好处**：老师本来就要问，你先说，显得有工程意识。

> 过渡：“登录之后，数据从哪来？看 `fileio.c`。”

### 2. `fileio.c` / `fileio.h`（约 80 秒）

> “数据存在一个文本文件里，这个模块负责它和内存链表之间的搬运。”

- **格式**：一行一条，空格分隔 `学号 姓名 班级 学期 课程 分数`；字段宽度与结构体一一对应；
- **加载**：`fscanf("%15s %31s %31s %15s %31s %f")`，定宽防溢出，返回 6 才算一条（`fileio.c:19-23`）；
- **建表**：尾插保持文件顺序，但 N 条总步数是 N(N−1)/2 —— **O(N²)**；
- **写**：录入用追加 O(1)；修改/删除用全量重写 O(N)。

**两个必须知道的坑**

1. **坏行会中断加载**：`fscanf` 遇到格式不对的行就返回，循环直接结束，后面所有记录都读不到；
2. **崩溃会丢数据**：全量重写用的是 `fopen("w")`，先截断再写；写到一半崩溃，原文件已经没了。正确做法是写临时文件 → `fsync` → `rename` 原子替换。

**一句加分话**：

> “删除一条记录要重写整个文件，N=10⁴ 时大约 1MB 写流量——这是文本存储的固有代价，规模上去就该换数据库。”

**取舍**：头插 O(1) 但会逆序，导出和调试都不方便，所以选尾插。

> 过渡：“数据进内存是一条链表，按学号查要 O(n)。怎么加速？哈希。”

---

### 3. `index.c` / `index.h`（约 80 秒）

- **问题**：按学号查是最高频操作；
- **哈希**：32 位 FNV-1a，逐字节「先异或、再乘素数」，无符号溢出天然取模（`index.c:17-25`）；
- **冲突**：链地址法，256 个桶，桶内单链头插；
- **查找**：平均 1 + α/2，α = N/256（`index.c:59-68`），已接入 `list.c` 的按学号查找与删除定位；
- **实测**：6 个学号落在 6 个不同桶（10/119/228/81/190/248）。

**主动说维护策略**：索引只在启动时建一次的话，增删后会出现新记录查不到、已释放节点残留索引（悬空指针）的问题。现在的做法是“写后重建”：录入/删除后立即 `index_build`（O(n)，千级数据微秒级）；索引未命中时回退整表遍历兜底，保证正确性优先。

> 过渡：“索引负责找，真正增删改的是链表。”

---

### 4. `list.c` / `list.h`（约 1 分 50 秒，**核心**）

- **节点**：不带头结点的单向链表；
- **尾插**：`list.c:20-38`，单次 O(n)；
- **查找**：按学号（`list.c:42-48`）/ 按复合键（`list.c:50-58`）；
- **删除**：双指针 `prev/cur`（`list.c:67-88`），三个特判——空表、删头、找不到；
- **批量删除**：term/course 传空串表示不限制，循环删到没有为止，O(k·N)；
- **改信息**：同号记录可能不相邻，必须扫到表尾统一改（`list.c:101-117`）。

**画图**：

```text
删除中间：  prev → cur → next   ⇒   prev → next
删除头：    head → cur → next   ⇒   head = cur->next
```

> 过渡：“有了链表和索引，业务在 `main.c`。”

---

### 5. `main.c`（约 70 秒）

- 流程：加载 → 建索引 → 登录 → 按角色进三套菜单；录入/删除后重建索引（写后重建约定）；
- 统计：筛选拍平成数组 → **选择排序**（`main.c:81-90`），比较次数固定 n(n−1)/2；
- 排名：名次 = 1 + 前面严格更高的人数，同分并列跳号（`main.c:104-111`）；
- 聚合：平均分/及格率一遍扫描，O(n)。

**真实数据**：高等数学 6 条 → 100 / 92 / 88 / 76.5 / 55.5 / 45。

> 过渡：“前面反复用到 `Student`，最后统一讲设计。”

### 6. `student.h`（约 40 秒）

- 一条记录 = 一人一课一学期（事实表）；
- 复合主键：学号+学期+课程；
- 定长数组、无指针，可整块拷贝落盘；代价是冗余字段要批量同步；
- 常量：`MAX_*_LEN`、`PASS_SCORE=60`、`DATA_FILE`。

> 过渡：“控制台讲完，最后是浏览器模式。”

### 7. `webui.c` / `webui.h`（约 60 秒）

- 单线程 `accept` 循环，只绑 `127.0.0.1`（`webui.c:500-563`）；
- 解析：请求行 → `strtok_s` 切查询串 → URL 解码；
- 路由：8 个 `/api/*`，先校验 token 再按角色拦截；
- 返回：`sprintf` 拼 JSON；
- 排序：统计用 qsort，表格用前端 `sort` + `localeCompare('zh')`。

**工程细节**：浏览器预连接不发数据，所以 `recv` 设 2 秒超时，否则单线程被卡死。

## 三、专题：桶排序（约 2 分钟，**重点**）

> “老师可能会问：排名能不能用桶排序做到 O(n)？我专门想过这个问题，先说结论——能，而且在我们这个场景里非常合适，但当前规模下收益不明显。”

### 3.1 先澄清一个概念混淆（20 秒）

> “系统里那 256 个‘桶’是**哈希桶**，是存储结构；桶排序是**排序算法**。两者只是都叫桶，没有关系。”

| | 哈希桶（本系统） | 桶排序 |
|---|---|---|
| 目的 | 加速查找 | 把数据排好序 |
| 分桶依据 | `hash(key) % 256` | 值域区间 [0,1) 或 [0,100] |
| 桶内 | 冲突链 | 再排序（插入/快排） |
| 复杂度 | 查找 O(1+α) | 平均 O(n+k)，最坏 O(n²) |

### 3.2 桶排序原理（30 秒）

```text
1. 把值域切成 k 个区间（桶）
2. 每个元素按值放进对应桶
3. 桶内单独排序（通常插入排序）
4. 按桶的顺序拼接
```

- 平均 O(n + k)：放桶 O(n)，桶内近似 O(1)，拼接 O(k)；
- 最坏 O(n²)：所有元素落进同一个桶；
- 空间 O(n + k)；
- 稳定性取决于桶内排序（用插入排序则稳定）。

### 3.3 为什么本系统适合（30 秒）

> “我们的排序键是分数，值域固定 0–100、保留一位小数，这是桶排序最理想的输入。”

- 把分数放大 10 倍取整，得到 **0~1000 的整数**；
- 于是桶排序退化成**计数排序**：1001 个计数器，不需要桶内排序；
- 时间 O(n + 1001)，空间 O(1001)；
- 天然稳定（同分按原顺序），正好满足并列名次的需求。

### 3.4 与排名结合（20 秒）

```text
从 1000 号桶往 0 号桶遍历：
    rank = 已出现人数 + 1
    该桶内所有记录名次相同 = rank
    已出现人数 += 该桶计数
```

排名也从 O(n²) 降到 O(n + k)。

### 3.5 为什么当前没用（20 秒）

> “n 只有千级，qsort 已经够快；桶排序要额外 1001 个计数器，n 小的时候初始化开销反而更大。”

| 方案 | n=13 时 | n=10 万时 |
|---|---|---|
| qsort | 约 50 次比较 | 约 170 万次比较 |
| 计数排序 | 要初始化 1001 个桶，**反而更慢** | 约 10 万次操作，**快一个量级** |

**结论**：算法没有绝对好坏，要看 n 和 k 的关系——**n ≫ k 时桶排序才划算**。

### 3.6 如果老师追问

- “那你为什么不用？”→ 规模小、实现简单优先，已在文档里列为改进方向；
- “桶排序稳定吗？”→ 取决于桶内排序；计数排序版本天然稳定；
- “浮点数能直接做桶吗？”→ 不能，要先量化（`round(score*10)`），否则浮点误差会导致同一个分数落进不同桶。

## 六、答辩预案

### 登录相关

| 问题 | 回答 |
|---|---|
| 为什么用 token 不用 Session Cookie？ | 无框架、无状态服务，token 放在 URL 最简单；缺点是会进日志，生产应放 Header |
| token 怎么生成？安全吗？ | `rand()%16` 拼 32 位 hex，演示够用；安全性不足，应换 CSPRNG |
| token 存在哪？ | 服务端会话链表（内存），进程重启即失效 |
| 多个地方登录？ | 允许，每次登录生成独立 token |
| 密码为什么明文？ | 演示简化；生产用 bcrypt + salt |
| 学生怎么防越权？ | 服务端 `force_param` 强制改写 id |
| 教师为什么不能删？ | 路由层按 role 拦截，不是前端隐藏按钮 |

### 桶排序相关

| 问题 | 回答 |
|---|---|
| 你的哈希是桶排序吗？ | 不是，哈希桶是存储结构，桶排序是排序算法 |
| 排名能用桶排序吗？ | 能，分数 0–100 一位小数 → 1001 个计数桶 → O(n+1001) |
| 为什么不用？ | n 小的时候初始化开销大于收益；n ≫ k 时才划算 |
| 桶排序最坏情况？ | 全落一个桶，退化为 O(n²) |
| 稳定吗？ | 计数排序版本稳定；桶内用插入排序也稳定 |

### 其它

| 问题 | 回答 |
|---|---|
| 尾插为什么 O(N²)？ | 每次走到表尾，总 N(N−1)/2 |
| 索引怎么保证不过期？ | 写后重建：录入/删除后立即 `index_build`，千级数据 O(n) 重建微秒级可接受 |
| 系统瓶颈？ | 尾插 O(N²)、排名 O(n²)，千级可接受 |

## 附：可展开的加分点

1. **FNV-1a 为什么先异或再乘**：先乘后异或的话，最后一个字节不参与乘法，雪崩性差；
2. **为什么 256 个桶**：2 的幂便于 `% 256` 优化成 `& 255`，256×8B 只有 2KB；
3. **qsort 比较器为什么不用 `fb - fa`**：float 相减截断成 0 会误判相等；
4. **单线程为什么必须设接收超时**：浏览器预连接不发数据会堵死 accept。
